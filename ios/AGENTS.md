# Workspace for iPhone: agent instructions

Workspace for iPhone is a workspace as a native SwiftUI app on iOS 26 with Liquid Glass, over the Workspace API ([docs/API.md](../docs/API.md)); the README says how to generate, build and run it. Ported from the RIVI monorepo's `apps/workspace-ios`; here it signs in to whichever workspace the person names, since every deployment has its own address. The repository-wide rules are in the root [AGENTS.md](../AGENTS.md).

## Structure

- `WorkspaceKit/` is a local Swift package (Swift 6 language mode, iOS 26 and macOS 15, no UIKit, so `swift build` and `swift test` run on a Mac, and on Linux in the `swift:6.2` image: Keychain is behind `#if canImport(Security)` and the chat's stream reads the whole answer there). `Sources/WorkspaceKit/Models/` holds every shape of API.md as a `Codable`, `Hashable`, `Sendable` struct, one file per section; `Auth/` the sign-in: `WorkspaceAddress` (what a person types, as the workspace's origin: `https://` added, HTTPS only, plain HTTP to this machine or a private network in a debug build, the same rules as `mobile/src-tauri/src/workspace.rs`), `Authenticator` (`/api/health` checked first, then Better Auth's `/api/auth/sign-in/email`, the second step for an authenticator app or a backup code with the two-factor cookie carried by hand and the workspace's `Origin`, and the sign-out; a `404` from the password endpoint is a workspace with Duo on, `passwordClosed`), `Credentials` (the session token, the workspace and the address) and the `TokenStore` protocol (Keychain in the app, memory in tests); `API/` the `WorkspaceClient` actor (the session token as a bearer, JSON, downloads, `documentRequest` for a web view; no refresh, so a `401` forgets the sign-in and calls `onAuthenticationLost`), `APIError`, the chat's `SSEParser` and `chatEvents`, and `Endpoints/` with one extension per section and one method per row of API.md. Add an endpoint there, with its shape in `Models/` and a case in `Tests/`. `Notifications/` holds what the reminders decide without UIKit: `NotificationRoute` (where a tap opens the app) and `ReminderPlan`, tested in `NotificationsTests`.
- `Workspace/` is the app: `App/` (`WorkspaceApp`, `AppModel`, `AppDelegate`, `RootView`, `MainTabView`, `TabToolbar` with `CreateMenu`, `CreateFlows`, `ChangeSignal`, `Server` (the address the sign-in screen offers: the last one signed in to, or `WORKSPACE_URL` in a debug build), the `workspaceClient` environment key), `Design/` (`Theme`, `Glass`, `Components/`), `Features/<Name>/` with the feature's root view and its model, `Resources/Assets.xcassets`, whose `AppIcon.png` is Workspace's symbol as `pnpm --filter @rivi/workspace-mobile run icons` writes it (opaque, 1024 px): change the icon there, never by hand.
- `project.yml` generates `RIVIWorkspace.xcodeproj` (`xcodegen generate`); both are committed, and a new file needs the generate run. The scheme is `Workspace`; the product is "RIVI Workspace", bundle id `software.rivi.workspace`, URL scheme `riviworkspace`. Edit files in place where you can: a file added or removed needs `xcodegen generate` on a Mac and the regenerated project committed, which CI builds as it is.

## Conventions

- One `@Observable @MainActor final class <Feature>Model` per feature, owned by its root view as `@State`, with its data in `LoadState<Value>` properties. The client comes from `@Environment(\.workspaceClient)` and the app's state from `@Environment(AppModel.self)`; pass the client into the model's methods. All UI runs on the main actor.
- Change a `LoadState` in synchronous steps around an `await` (`begin()`, then `finish(value)` or `fail(error)`), as the root views do; never through a mutating call that spans the `await`, which holds an exclusive access while SwiftUI reads the property.
- Errors reach the person through `ErrorBanner` with the server's words (`APIError.server` carries them; `error.localizedDescription` is enough), through `LoadStateView` for a screen's data. A cancelled load shows nothing (`failureMessage`).
- Every list is `.refreshable`. Every tab's root view carries `.tabToolbar()` (the Assistant at the top left, opening in a sheet, the avatar that opens Settings and the create menu at the top right; a root's own leading item follows a `ToolbarSpacer(.fixed, placement: .topBarLeading)`, as Calendar's Today) and a `.navigationTitle`, and one whose data can change elsewhere `.reloadsWhileOpen` (`App/ReloadWhileOpen.swift`: back from the background and once a minute while on show, as the console's `useRefresh`), or what was archived in the browser stays in the app's list. A reload keeps what the person scrolled to: Mail's `load` fetches as many pages as were shown.
- A `.toolbarTitleMenu` (Mail's folders, Drive's views) opens only from an inline title, so its root view sets `.navigationBarTitleDisplayMode(.inline)`; a large title shows no chevron and ignores the tap until the list scrolls.
- Dates are `Date` from the tolerant ISO 8601 decoder; days stay `DayKey` (`YYYY-MM-DD`). Every wire enum is a `WireEnum` with an `.other(String)` case, so switch over it with `.other` handled. A request field that must be `null` rather than absent has a custom `encode(to:)` (`NewFolder`, `MoveRequest`, `ChatRequest`, `TaskInput.dueOn`).
- Files stay under 400 lines; no force unwraps (a precondition with words where a value cannot be missing); no third-party packages; no `print`.
- Copy is plain American English in sentence case, no em dashes, no exclamation marks, strings inline (no localization yet). The brand's colors are `Theme`; type is the system's.
- RIVI's marks are drawn from their geometry in `Design/Components/BrandMarks.swift`, never as images: `WorkspaceSymbol` (the app icon's four tiles, one lit) on the sign-in screen, `WorkspaceLoader` (its lit tile walking) for a screen's first load through `LoadStateView` and `LoadingSection`, and `SignalMeter` (the RIVI mark's bars) as the Assistant's face and its thinking. One element lit in the signal green is the identity's grammar: spend the accent on what is live or primary (unread, today, the primary action), not on decoration. A tile that echoes the mark rounds its corners by `Theme.tileCorner(_:)`.
- Rows scale with Dynamic Type up to the accessibility sizes: a side column (the agenda's times, a mail row's avatar) stacks or steps aside there rather than squeezing the words; the month grid caps its type at `xxLarge`.
- Notifications live in `Features/Notifications/`: `NotificationsModel`, which `AppModel` owns and hands the client (the system's callbacks in `AppDelegate` come without one), and the Settings section. This workspace's Worker sends no push, so there is no notification of new mail and no device to register; calendar and task reminders are local notifications the app plans itself from `/calendar` and `/tasks` each time it comes to the front (`ReminderPlan`, identifiers under `reminder.`, at most 60 of iOS's 64). A tap sets `NotificationsModel.route`; `MainTabView` selects the tab, and `CalendarRootView` opens the event. The choices stay in `UserDefaults` on the phone.
- A message's HTML goes in a `WKWebView` loading `client.documentRequest(messageId:appearance:images:)`, never rendered any other way; the attachment's `url` is a signed link, `client.download(attachment:)`.
- Sign-in is `SignInView` with its `SignInModel`: the workspace's address, the person's address and password, then the code where the account has one. `AppModel.signedIn` makes the `WorkspaceClient` for the workspace signed in to (a new one for another workspace) and remembers the address (`Server.remembered`); the client goes in the environment as `workspaceClient`. A workspace's Assistant can be off (`Me.assistant.enabled`, `AppModel.assistantEnabled`): the toolbar then has no Assistant. Tasks link to GitHub issues (`TasksData.github`, `POST /tasks/from-issue`), never anything else.
- Shared group inboxes: `Me.mailboxes` lists them, Mail's title menu switches (`AppModel.showMailbox`, `AppModel.box`), and every Mail call takes `box` (the API's `?box=`): `MailModel` keeps the box it lists, and the conversation, the composer, the label picker and a message's document are made with it, passed down explicitly rather than through the environment, since a pushed destination does not see a value set inside the stack. The create menu's new message comes from the mailbox Mail shows, as in the console. A message a member wrote in a shared inbox carries `sentBy`, shown on its card.

## Liquid Glass

- The system's bars, tabs, sheets and toolbars are glass by default: leave them. Put `.glassEffect` only on controls that float over content (a compose button, a bottom action bar), through `GlassIconButton`, `GlassPillLabel`, `GlassCard`; group neighbors in `GlassGroup` (`GlassEffectContainer`) so they blend; never glass on glass.
- A screen's one primary action is `.prominentAction()` (the prominent glass with its label in `Theme.onAccent`, which reads on the signal green of the dark appearance where white does not); a floating one is `GlassIconButton(…, prominent: true)` placed by `.floatingAction`, bottom trailing (the Assistant's new conversation, in its sheet). Secondary floating actions are `.buttonStyle(.glass)`.
- The tabs make things from one create menu, not a floating action per screen: a system `Menu` with a `primaryAction` (`CreateMenu`) at the far right of every tab's bar (`.primaryAction` placement in `tabToolbar`, and in a pushed Drive folder), tinted with the accent as the screen's primary action. A tap makes the shown tab's thing (`CreateKind.primary(for:)`: a message, an upload, an event, a task; compose on Mail, a plus elsewhere), and a press and hold opens the system's menu of everything the workspace makes, the shown tab's section first. The tab comes from `\.appTab`, which `MainTabView` sets on each stack. `createFlows` opens the composer, the editors and Drive's flows over whichever tab is on show; a new event starts on Calendar's selected day and a folder or upload goes to the Drive folder on show (`CreateCenter`), else today and My Drive. What was made reaches the lists through `ChangeSignal` (`mail`, `planner`, `drive`): a list that shows it reads itself again when the signal's `version` moves. A new kind is a case of `CreateKind` and of `createFlows`.
- The tab bar is the system's and never shrinks (`.tabBarMinimizeBehavior(.never)` in `MainTabView`): iOS reports neither its shrinking nor its growing. On iOS 27.2 nothing native sits beside the full bar: a `role: .search` tab and `.tabViewBottomAccessory` move beside it only once it shrinks, so the create menu is in the top bar. `ToolbarSpacer` separates toolbar groups; items from an outer `.toolbar` come first, adjacent ones share one glass, and `.primaryAction` stays last. `.scrollEdgeEffectStyle` and `.backgroundExtensionEffect` are for content that should run under a bar.
- Every API named in the foundation's brief compiled against the iOS 27.2 SDK: `.glassEffect`, `GlassEffectContainer`, `.buttonStyle(.glass)`, `.buttonStyle(.glassProminent)`, `.glassEffectID`, `ToolbarSpacer`, `.scrollEdgeEffectStyle`, `.backgroundExtensionEffect`, `.tabBarMinimizeBehavior`, `.tabViewBottomAccessory`. None was dropped.

## Checks

`cd WorkspaceKit && swift build && swift test` for the package (on Linux: `docker run --rm -v "$PWD:/pkg" -w /pkg swift:6.2 swift test`, from `WorkspaceKit/`); `xcodebuild -project RIVIWorkspace.xcodeproj -scheme Workspace -destination 'generic/platform=iOS Simulator' -configuration Debug CODE_SIGNING_ALLOWED=NO build` for the app. CI (`.github/workflows/ios.yml`) runs the package's tests on Linux and the app's build on a Mac with the newest Xcode on the runner, when a pull request changes `ios/`. There is no release job.
